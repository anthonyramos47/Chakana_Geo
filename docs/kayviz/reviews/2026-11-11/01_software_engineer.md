# kayviz code-quality and architecture review (software engineer, branch `debugging`)

## 1. Summary
- Runtime now well structured: pushes in-process, clean binary wire format, 100 tests pass in 15 s. B1, B3, B4, B5, B12, B14, B19 from REVIEW_2026-11 fixed.
- Moving handlers off the event loop created new concurrency gaps in GUIApp, all reproduced: two "run" streaming tasks can drive one state at once; a sync action can run in a thread while a streaming task runs; another tab's `_set_state` can change the state while a sync handler uses it.
- The scene is kept in two buffers (ScriptApp and CallbackApp) that can disagree: kv.remove inside a callback, remove(mesh) with quantities, and pushes during schema capture leave stale objects that come back on reload.
- Process-global state does not survive a server restart in the same process (kill_servers() then show()): asyncio Event/Lock bound to the old loop → /wait returns 500 and show(block=True) hammers it ~300×/s.
- Before release: no Origin check (any web page can shut the server down or drive the WebSockets); requires-python>=3.9 false (serializers.py fails to import on 3.9); the docs' own streaming example blocks the event loop.

Still open from REVIEW_2026-11: B7 (screenshot.js:139), B8 (viewer.js:140-150), B9 (SceneEntry.js:200), B10, B11, B13 (script.py:808), B16 (script_app.py:153), B20 (script_panel.js ships). B6 half fixed (SE17).

## 3. Top 5 recommendations
1. Per-app execution policy (SE1, SE2, SE21; small): one streaming task, sync handlers and _set_state behind it except stop; fix the streaming example; regression tests.
2. One scene store per server (SE4, SE5, SE6; medium): remove/clear as sink markers, schema capture under the sink, drop name::* on remove.
3. Restart-safe runtime (SE3, SE16, SE11; small): recreate Events/Locks per loop, reset client state, sleep on errors, keep task refs; kill_servers()+init() test.
4. Release blockers (SE7, SE8, SE19; small): Origin check + shutdown token, 3.9 import fix + CI, readme, optional deps.
5. Fail loudly (SE9, SE12, SE13, SE14): np.generic/NaN/int64 in encode, input validation, generated wrappers, delete dead code.
